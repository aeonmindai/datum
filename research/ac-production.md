# Production multi-agent / coding-agent shared state and mission representation (as of 2026-08-24)

Scope: what real shipped systems use for shared state and goal/mission coordination. Protocol specs (MCP/A2A/ANP/AGNTCY) and durable-execution internals (Temporal/Inngest/Restate/LangGraph/Ray/Dapr/DO) are out of scope by assignment.

---

## Direct answers

### 9a. What do real production multi-agent systems use for shared state TODAY?

**Repo files, git branches/PRs, and per-session blobs. The expected answer is correct, and the vendors say so in their own docs.** Evidence, not inference:

- **Git branches are the handoff medium, stated explicitly.** Devin: a child agent "cannot see the orchestrating session's files, so **code handoffs go through git branches**: each agent pushes a branch and reports the branch name" (<https://docs.devin.ai/work-with-devin/dynamic-workflows>). Cursor: cloud agents "work on a separate branch, then **push changes to your repo for handoff**" (<https://cursor.com/docs/cloud-agent>). Copilot: "one branch at a time and can open exactly one pull request to address each task" (<https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent>). Codex cloud: the reviewable unit is "the summary and diff… or open a pull request" (<https://learn.chatgpt.com/docs/cloud>).
- **Repo files are the shared instruction memory**, standardised as `AGENTS.md`, "used by over 60k open-source projects," now stewarded by the Agentic AI Foundation under the Linux Foundation, with 20+ named adopters (<https://agents.md/>). Conflicts resolve by file proximity, not by data: "The closest AGENTS.md to the edited file wins" (same URL).
- **Per-session blobs are the state**: ADK `session.state` is a mutable serializable dict (<https://adk.dev/sessions/state/>); OpenAI Agents SDK Sessions are an item list per session id with `pop_item()`/`clear_session()` (<https://openai.github.io/openai-agents-python/sessions/>); Replit checkpoints are whole-environment snapshots (<https://docs.replit.com/features/version-control/checkpoints-and-rollbacks>).
- **Where a system does better, it is still a filesystem.** Anthropic's artifact store is "Subagent output to a filesystem" (<https://www.anthropic.com/engineering/multi-agent-research-system>). Manus: "we treat the file system as the ultimate context" (<https://web.archive.org/web/20260101231329/https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus>). OpenHands persistent memory is `MEMORY.md` capped at ~6,000 characters (<https://docs.openhands.dev/sdk/guides/persistent-memory>). Claude Code agent teams coordinate through `~/.claude/teams/{team}/inboxes/{agent}.json` and `~/.claude/tasks/{team}/` with file locking (<https://code.claude.com/docs/en/agent-teams>).
- **The two genuine exceptions, both partial.** (i) **GitHub Copilot Memory** — a hosted fact store with citations validated against the current branch, write access gating, repo/user scope split, and a 28-day unused-entry TTL (<https://docs.github.com/en/copilot/concepts/agents/copilot-memory>). (ii) **Devin Knowledge** — org/enterprise-scoped items with mandatory retrieval triggers and repo pinning (<https://docs.devin.ai/product-guides/knowledge>). Neither is versioned, neither has confidence classes, neither raises contradictions at write time, and neither retains a superseded record.

**Nobody has a durable, queryable, provenanced shared fact store across concurrent agents.** Cognition states the gap directly: "At the moment, I don't see anyone putting a dedicated effort to solving this difficult cross-agent context-passing problem" (<https://cognition.com/blog/dont-build-multi-agents>). **Nobody stores a superseded record** — every system corrects by deleting or overwriting. **Nobody rejects a write for missing provenance.** **Nobody has assert-time.**

### 9b. What is the state of the art for "what is the current mission"?

**Mostly re-pasting a prompt. But there are four real counter-examples, and they are all weaker than a first-class mission object with machine-checkable gates.**

The honest baseline: Anthropic's lead agent saves its plan to "Memory" as a text blob so a >200k-token context truncation does not lose it (<https://www.anthropic.com/engineering/multi-agent-research-system>); Manus rewrites `todo.md` every step to "recite its objectives into the end of the context" (archived URL above); Devin Playbooks and Cursor/Factory rules are reusable *prompt templates*, not goal state (<https://docs.devin.ai/product-guides/using-playbooks>, <https://cursor.com/docs/rules>, <https://docs.factory.ai/harness/agents-md>). Effort allocation is prose in a prompt, not a field: "Simple fact-finding requires just 1 agent with 3-10 tool calls" (Anthropic, same URL).

The counter-examples, ranked by how close they come:

1. **OpenHands Conversation Goals — the strongest.** A goal is a real server-side object with `POST /goal`, `/goal/stop`, `/goal/resume`; status ∈ `{running, complete, capped, interrupted}`; a typed `GoalVerdict{score, complete, missing}` from an **independent judge LLM**; and status persisted into the event log "so resume can work after a server restart." Terminal statuses are non-resumable; concurrent goals 409 (<https://docs.openhands.dev/sdk/guides/agent-server/conversation-goals>, <https://docs.openhands.dev/sdk/guides/convo-goal>). **The gate is an LLM verdict, not a predicate.**
2. **Claude Code agent teams' shared task list — the strongest *enforcement*.** Three states, explicit dependencies where "a pending task with unresolved dependencies cannot be claimed," automatic unblocking, atomic claiming via file locking, and **`TaskCreated`/`TaskCompleted`/`TeammateIdle` hooks where "Exit with code 2 to prevent completion and send feedback"** (<https://code.claude.com/docs/en/agent-teams>). This is the only machine-enforced reached/not-reached gate I found in a shipped coding agent. **It is single-machine, unversioned, experimental, and off by default.**
3. **Spec-driven tooling — targets as prose.** Spec Kit: loop `implement`→`converge` "until `/speckit.converge` reports **Converged**," with `/speckit.checklist` described as "unit tests for English" (<https://raw.githubusercontent.com/github/spec-kit/main/README.md>; 131k stars, <https://github.com/github/spec-kit>). Kiro: `requirements.md`/`design.md`/`tasks.md` with acceptance criteria in EARS notation (<https://kiro.dev/docs/specs/>) — and EARS is explicitly a natural-language discipline that "gently constrains free-form natural language," not a predicate language (<https://en.wikipedia.org/wiki/Easy_Approach_to_Requirements_Syntax>).
4. **Mission-shaped containers without targets.** Devin Spaces group "agent sessions, PRs, files, and context" for a task and let new sessions inherit context via `devin.spaces.shareContext` (<https://docs.devin.ai/desktop/spaces>). GitHub issue-as-spec + one-PR-per-task is the same thing in a tracker (<https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent>).

**Nobody models goals with formal machine-checkable reached/not-reached predicates.** Every gate in production is either an LLM judgement (OpenHands judge, Spec Kit `converge`, Kiro EARS prose) or an arbitrary shell hook that a human wrote (Claude Code hooks). **Nobody has a mission object that spans machines, projects, or agents.** **Nobody attaches evidence requirements to a target** — no system says "this target is reached only when metric X is asserted with confidence class `measured`." **Nobody versions the mission**: OpenHands' resume rebuilds "the controller with the same objective and stored iteration," so an edited objective is a new goal with no recorded history of the old one.

## What exists

### 1. Anthropic Research (orchestrator–subagent), Jun 13 2025

- Orchestrator-worker: a `LeadResearcher` plans, then spawns parallel subagents; subagents "act as intelligent filters," search independently, and **return findings to the lead**. Source: <https://www.anthropic.com/engineering/multi-agent-research-system>
- **The plan is written to "Memory" as an explicit durability mechanism**: "The LeadResearcher begins by thinking through the approach and saving its plan to Memory to persist the context, since if the context window exceeds 200,000 tokens it will be truncated and it is important to retain the plan." Same URL. This is the closest thing to a mission object in the post — and it is a text blob in an external store, retrieved on context overflow.
- **Filesystem as artifact store to avoid the coordinator bottleneck**: "Subagent output to a filesystem to minimize the 'game of telephone.' … Subagents call tools to store their work in external systems, then pass lightweight references back to the coordinator." Same URL (Appendix).
- Token economics, published numbers: multi-agent (Opus 4 lead + Sonnet 4 subagents) beat single-agent Opus 4 by **90.2%** on their internal research eval; on BrowseComp three factors explained **95%** of performance variance, with **token usage alone explaining 80%**; agents use **~4× more tokens than chat**, multi-agent **~15× more than chat**. Parallelization (3–5 subagents in parallel, 3+ parallel tool calls each) cut research time **up to 90%**. Same URL.
- Prompted effort scaling is hardcoded in the prompt, not a data structure: "Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each, and complex research might use more than 10 subagents." Same URL.
- **Stated failure modes (their words)**: early agents spawned **50 subagents for simple queries**; subagents "distracting each other with excessive updates"; duplicated work from vague task descriptions (one subagent researched the 2021 auto chip crisis while two others duplicated 2025 supply-chain work); agents preferring "SEO-optimized content farms over authoritative but less highly-ranked sources"; **synchronous execution is an admitted bottleneck** — "the lead agent can't steer subagents, subagents can't coordinate, and the entire system can be blocked while waiting for a single subagent." Same URL.
- Evaluation: end-state, not trace-based — "evaluate whether it achieved the correct final state… break evaluation into discrete checkpoints where specific state changes should have occurred." Same URL. LLM-as-judge with a 0.0–1.0 score plus pass/fail was more consistent than multiple judges. Same URL.

### 2. Claude Code: subagents, agent teams, cross-session messaging

This is the most concrete production coordination substrate I found in a shipped coding agent, and it is a filesystem.

- **Subagents**: own context window, own system prompt, own tool allowlist; results return to the caller. Defined as Markdown + YAML frontmatter in `.claude/agents/` (project) or `~/.claude/agents/` (user). Precedence, highest first: managed settings → `--agents` CLI JSON → `.claude/agents/` → `~/.claude/agents/` → plugin `agents/`. Source: <https://code.claude.com/docs/en/sub-agents>
- Isolation is worktree-based: `isolation: worktree` gives a subagent its own repo copy, and Claude Code blocks Bash commands whose working directory resolves back to the main checkout, blocks commands that redirect git into the main checkout, and refuses commands whose shape it cannot verify stay inside the worktree. Same URL.
- **Agent teams (experimental, off by default behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`)**: a lead plus teammates, each a full independent session, with **a shared task list and per-agent mailboxes**. Source: <https://code.claude.com/docs/en/agent-teams>
  - Mailbox: "Each agent's mailbox is a JSON file at `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`." Same URL.
  - Team config at `~/.claude/teams/{team-name}/config.json`; task list at `~/.claude/tasks/{team-name}/`; team name is `session-` + first 8 chars of the session ID. Team config dir is deleted on session exit; task dir persists and is "never uploaded," retained per `cleanupPeriodDays`. Same URL.
  - **Tasks are first-class enough to matter**: three states (pending / in progress / completed), **explicit dependencies** ("a pending task with unresolved dependencies cannot be claimed"), automatic unblocking of dependents on completion, and **"Task claiming uses file locking to prevent race conditions."** Same URL.
  - **Gates exist as hooks**: `TaskCreated`, `TaskCompleted`, `TeammateIdle` — "Exit with code 2 to prevent completion and send feedback." Same URL. This is the only machine-enforced reached/not-reached gate I found in a shipped coding agent.
  - Explicit cost warning: teams "use significantly more tokens than a single session"; token cost is "Higher: each teammate is a separate Claude instance." Same URL.
  - Known-limitations warning on the page itself: "Agent teams have known limitations around session resumption, task coordination, and shutdown behavior." Same URL.
- **Cross-session messaging** (v2.1.224+ macOS/Linux, v2.1.234+ native Windows): "A message is a piece of text one Claude writes to another, **never conversation history or files**." Local delivery is over a per-session Unix domain socket (named pipe on Windows), "never through Anthropic servers"; cross-machine goes through Anthropic servers via Remote Control. Source: <https://code.claude.com/docs/en/cross-session-messaging>
  - Hard boundaries: a peer message "can't approve anything," can't change `CLAUDE.md` or permission settings, and slash commands in message text arrive as plain text and are never executed. Same URL.
  - Concrete limits: at most **100 held messages** (oldest dropped past that); held-message expiry defaults to **5 minutes** (`dialogExpiry`); an idle-notification subscription is **one-shot and expires after 12 hours**. Same URL.
  - Filesystem-scoped discovery, with the failure mode stated: "A container has its own filesystem, so a session inside it and a session on the host can't reach each other." Same URL.

### 3. Cognition / Devin

- **The essay**: Walden Yan, "Don't Build Multi-Agents," 2025-06-12. Two principles: "Share context, and share full agent traces, not just individual messages" and "Actions carry implicit decisions, and conflicting decisions carry bad results." He names OpenAI Swarm and Microsoft AutoGen as "actively push[ing] concepts which I believe to be the wrong way of building agents." Source: <https://cognition.com/blog/dont-build-multi-agents>
- He explicitly says the cross-agent state problem is *unsolved and unattended*: "in 2025, running multiple agents in collaboration only results in fragile systems… At the moment, I don't see anyone putting a dedicated effort to solving this difficult cross-agent context-passing problem." Same URL.
- His recommended architecture for long tasks is **a fine-tuned compression model**, not a shared store: "we introduce a new LLM model whose key purpose is to compress a history of actions & conversation into key details, events, and decisions… Depending on the domain, you might even consider fine-tuning a smaller model (this is in fact something we've done at Cognition)." Same URL.
- **Cognition shipped multi-agent anyway.** Devin's "Managed Devins": a coordinator "scopes the work, monitors progress, **resolves conflicts**, and compiles results," spinning up child sessions "each running in its own isolated VM," with the coordinator able to message children, monitor ACU consumption, sleep/terminate them, and **schedule messages to itself** to check back. Source: <https://docs.devin.ai/work-with-devin/advanced-capabilities>
- **Devin Dynamic Workflows** — the most sophisticated orchestration primitive I found, and it is content-addressed memoization, not shared memory: "a deterministic Python script that orchestrates a team of Devin agents… **each agent call is keyed by a hash of its prompt, schema, and execution settings**. Everything that already completed replays from its recorded result." Determinism is a hard requirement: "Workflow logic and prompts must not depend on the current time or date, randomness, generated IDs, environment variables, filesystem state, or network responses." Run budget: "The default and maximum budget for a run is **seven days**." Source: <https://docs.devin.ai/work-with-devin/dynamic-workflows>
- **The shared-state answer is git branches, stated outright**: a default separate-VM agent "cannot see the orchestrating session's files, so **code handoffs go through git branches**: each agent pushes a branch and reports the branch name, and later stages read it from the structured output." Shared-VM mode exists but "parallel writers must be given strictly non-overlapping files or directories." Same URL.
- **Devin Knowledge** is the closest production analogue to a scoped fact store: items with a mandatory **Trigger Description** for retrieval, per-user enable/disable, nested folders, repo pinning (no repo / one repo / all repos), org scope vs **Enterprise scope**, and "Promote to Enterprise." Retrieval is deliberately lazy: "Devin retrieves Knowledge when relevant, not all at once or all at the beginning." Source: <https://docs.devin.ai/product-guides/knowledge>
- Devin does contradiction handling — as an LLM chore, on request: "Find and merge duplicate knowledge entries / **Resolve conflicting guidance** / Create new knowledge from codebase patterns," typically run on a schedule ("every Monday at 8 AM to review pending knowledge suggestions, deduplicate entries, and resolve conflicting guidance"). Source: <https://docs.devin.ai/work-with-devin/advanced-capabilities>
- **Devin Spaces** (in Devin Desktop, the former Windsurf) is a mission-shaped *container* without targets: "A Space groups everything related to a specific task or project into a single view: agent sessions, PRs, files, and context… When you create a new session in a Space, it inherits everything the Space already knows about the project. Context sharing is controlled by the `devin.spaces.shareContext` setting." Source: <https://docs.devin.ai/desktop/spaces>
- Devin also reads `AGENTS.md` (<https://docs.devin.ai/onboard-devin/agents-md>) and uses git worktrees for parallel local tasks (<https://docs.devin.ai/desktop/cascade/worktrees>).

### 4. Cursor

- **Cloud Agents (renamed from Background Agents — the page says so explicitly under "Naming History")**: isolated VMs, and the shared-state mechanism is the repo: "Cloud agents clone your repo from GitHub, GitLab, Azure DevOps Services, or Bitbucket Cloud and **work on a separate branch, then push changes to your repo for handoff**." Source: <https://cursor.com/docs/cloud-agent>
- "You can run as many agents as you want in parallel." There is **no cross-agent shared memory** described on the page — coordination is branches, PRs, and per-run artifacts (screenshots, videos, logs). Same URL.
- Sharing is read-only by default and access-checked against repo permissions, not team membership: "Team membership alone doesn't grant access." Same URL.
- Hooks run from `.cursor/hooks.json` in the repo (Enterprise adds team and enterprise-managed hooks); `~/.cursor/hooks.json` user hooks do **not** run in cloud because "cloud VMs don't have access to your local home directory." Same URL.
- **Memory model is files with frontmatter, plus a dashboard tier.** Four rule types: Project Rules (`.cursor/rules/*.mdc`, version-controlled), User Rules, **Team Rules (dashboard-managed, Team/Enterprise, and they "take precedence")**, and `AGENTS.md`. Activation is `alwaysApply` / `globs` / `description` / `@`-mention. `.md` files in `.cursor/rules` are silently ignored because they carry no frontmatter. Guidance: "Keep rules under 500 lines." Source: <https://cursor.com/docs/rules>

### 5. Factory (Droids)

- Shared state is `AGENTS.md`, and Factory publishes **the only hard context caps I found for repo-file-as-memory**: "Initial AGENTS-style guideline load: **80,000 characters**. Dynamic Read-path guideline discovery: **40,000 characters**." Source: <https://docs.factory.ai/harness/agents-md>
- Discovery walks from cwd up to the git root, checking each directory plus `.factory/`, `.agents/`, `.agent/`, then `~/.factory/`, `~/.agents/`, `~/.agent/`. Compatible filenames include `CLAUDE.md`. Precedence model: current user request > nested project files > root project files > personal defaults. Same URL.
- Surfaces are split by load semantics: `AGENTS.md` (always-on), `DESIGN.md` (always-on design), `SKILL.md` ("full body loads when invoked"), `.factory/commands/*`, `.factory/settings.json`. Same URL.
- Factory's own doc says the anti-pattern is putting mission state in the file: avoid "Temporary task notes that belong in an issue, PR, or spec." Same URL. **I could not find a primary Factory doc describing cross-droid shared state or parallel droid coordination.** Noted as a gap.

### 6. Replit Agent 3

- Autonomy numbers: "Agent 3 runs on its own for up to **200 minutes**"; "**10x more autonomous**"; self-testing in a real browser is "**3x faster and 10x more cost-effective than Computer Use models**." Max Autonomy behaviors: extended sessions, "**Task management**: Agent able to create and work through longer task lists," self-supervision. Published Sep 10 2025. Source: <https://replit.com/blog/introducing-agent-3-our-most-autonomous-agent-yet>
- Agents-building-agents is real but is app generation, not coordination: "Agent 3 can build other agents and automations," deployed to Telegram/Slack/email surfaces. Same URL.
- **Checkpoints are whole-environment snapshots that explicitly include agent memory**: each checkpoint preserves "Project files… **AI conversation context**… Environment configuration… **Agent memory**: The AI's understanding of your project architecture, preferences, and patterns… Database contents." Source: <https://docs.replit.com/features/version-control/checkpoints-and-rollbacks>
- Rollback is **destructive**: "When you use the rollback feature, you restore the Replit App to a previous state. **This removes all changes made after that point**, including code edits." Roll-forward exists but only until you diverge: "Once you make new changes after a rollback, those future checkpoints become part of an alternate branch of history." Database rollback is opt-in and production DB is excluded. Each checkpoint also creates a corresponding git commit. Same URL.
- Replit shipped always-on instruction injection in Jun 2026: "Custom Instructions are always-on guidelines injected automatically into the agent's context on every project, every session, before anyone types a single word." Source: <https://replit.com/blog/custom-skills>

### 7. OpenHands (All-Hands-AI) — the only OSS system with a real event log *and* a real goal object

- **Append-only typed event log is the architecture**: "Events form an **append-only log** that serves as both the agent's memory and the integration point for auxiliary services," with immutable Pydantic models carrying ID, timestamp, and `source`. Source: <https://docs.openhands.dev/sdk/arch/events>
- The event framework separates **attribution from presentation** — a distinction directly relevant to provenance: "`Event.source`: where the event *originated* (`user`, `agent`, or `environment`). This is about attribution. LLM `role`… is about LLM formatting. These fields are **intentionally independent**. … **Do not infer event origin from LLM role.**" Same URL.
- Compression is modelled as events, not deletion: `Condensation` carries `forgotten_event_ids`, `summary`, `summary_offset`. Same URL.
- **Goal Completion Loop — a genuine machine-driven reached/not-reached gate**, with an independent judge: "after each run it asks a second **judge LLM** to audit the transcript for authoritative evidence — file contents, command output, test results — that the objective is *provably* complete." `GoalVerdict` = `{score: float 0–1, complete: bool, missing: str}`; `GoalOutcome.status` ∈ `{"complete", "capped"}`; `max_iterations` default 10. Failure is conservative: "If the judge response cannot be parsed as JSON, the verdict falls back to `score=0.0, complete=False`." Source: <https://docs.openhands.dev/sdk/guides/convo-goal>
- **Goals are resumable server-side objects**: `POST /api/conversations/{id}/goal`, `/goal/stop`, `/goal/resume`; status ∈ `{running, complete, capped, interrupted}` emitted as `ConversationStateUpdateEvent` with `key="goal"`, carrying `active`, `iteration`, `max_iterations`, `objective`, `verdict`. "These status events are **persisted with the conversation events, so resume can work after a server restart**." Terminal statuses are non-resumable; 409 if another goal is running. Source: <https://docs.openhands.dev/sdk/guides/agent-server/conversation-goals>
- **Persistent memory is Markdown with a character budget and an untrusted-content wrapper**: two tiers (`~/.openhands/memory/` user, `<workspace>/.openhands/memory/` project), each with a curated `MEMORY.md` index plus never-auto-loaded `YYYY-MM-DD.md` daily logs. "The combined indexes are capped at **~6,000 characters**. When the budget is exceeded, whole lines are dropped from the top of each over-budget tier (the oldest content)." Injected inside `<UNTRUSTED_CONTENT>`: "the agent is told they may contain prompt injection, and to treat them as unverified hints, **never as authoritative instructions**." Opt-in, off by default. Source: <https://docs.openhands.dev/sdk/guides/persistent-memory>

### 8. GitHub Copilot cloud agent + Copilot Memory — the closest production system to a provenanced fact store

- **Copilot Memory stores repository-level facts *with citations*, and validates them against the current branch before use**: "Repository-level facts are stored with **citations pointing to the code that supports them**. When Copilot finds a fact relevant to its current work, **it checks those citations against the current branch to confirm the information is still accurate. Only validated facts are used.**" Source: <https://docs.github.com/en/copilot/concepts/agents/copilot-memory>
- Write authority is gated: "Copilot only creates repository-level facts in response to actions by users **with write access** to the repository who have Copilot Memory enabled." Facts are repo-scoped and usable only "in operations on the same repository." Same URL.
- Two scopes with different sharing: repository-level facts (shared to all with access) vs user-level preferences (private to the user, owned by the **billing entity**, exportable/deletable by org/enterprise admins on Business/Enterprise). Cross-feature: facts learned by cloud agent are usable by code review and CLI; "Copilot code review uses repository-level facts only." Same URL.
- **Retention is a TTL, and it deletes**: "any stored fact or preference that goes unused is **automatically deleted after 28 days**. The 28-day timer may reset whenever Copilot successfully validates and uses an entry." Same URL.
- Cloud agent hard limits: "**Copilot can only work on one branch at a time** and can open exactly one pull request to address each task"; "Each Copilot cloud agent session has a maximum execution time of **59 minutes**. This is a hard limit that cannot be extended or bypassed"; single-repo only ("Copilot cannot make changes across multiple repositories in one run"); ephemeral environment powered by GitHub Actions. Source: <https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent>
- GitHub's own framing of *why* this beats IDE-local work is a provenance argument: with IDE assistants "Decisions made during the session are **untracked** and lost to time unless committed," whereas on GitHub "every step happening in a commit and being viewable in logs." Same URL.

### 9. OpenAI Codex cloud

- Parallel isolated cloud environments per repository; work starts from web, GitHub, GitLab (Beta), Linear, or Slack; the reviewable unit is "the summary and diff… or open a pull request." No shared cross-task state is described. Source: <https://learn.chatgpt.com/docs/cloud>
- Codex is the origin of the `AGENTS.md` convention (see below).

### 10. Aider — derived structural index, no embeddings

- The repo map is a **derived projection**, regenerated rather than stored: "a list of the files in the repo, along with the key symbols which are defined in each file," selected by "a **graph ranking algorithm**, computed on a graph where each source file is a node and edges connect files which have dependencies." Budget: "`--map-tokens` switch, which defaults to **1k tokens**," adjusted dynamically. Source: <https://aider.chat/docs/repomap.html>
- Notable negative: no embedding/vector step anywhere in the described pipeline.

### 11. The `AGENTS.md` convention — the de facto industry answer

- Adoption claim, with a reproducible query: "used by over **60k open-source projects**," linking `https://github.com/search?q=path%3AAGENTS.md+NOT+is%3Afork+NOT+is%3Aarchived&type=code`. Source: <https://agents.md/>
- Governance moved to a foundation: "AGENTS.md is now stewarded by the **Agentic AI Foundation** under the Linux Foundation." Same URL.
- Listed adopters include Codex, Jules, Factory, Aider, goose, opencode, Zed, Warp, VS Code, Devin, Junie, Amp, Cursor, RooCode, Gemini CLI, Kilo Code, Phoenix, Semgrep, GitHub Copilot coding agent, Ona, Windsurf, Augment Code, UiPath. Same URL.
- Conflict resolution is nearest-file-wins, prompt-overrides-all: "The closest AGENTS.md to the edited file wins; explicit user chat prompts override everything." Scale data point: "at time of writing the main OpenAI repo has **88 AGENTS.md files**." Same URL.

### 12. Framework state stores — none offer versioned or provenanced facts

- **Google ADK**: `session.state` is "a collection (dictionary or Map) holding key-value pairs," values "must be **serializable**… Stick to basic types," and "**Mutability: It Changes**." Scoping is by key prefix — no prefix = session, `user:` = per user across sessions, `app:` = per app across all users, `temp:` = per invocation and non-persistent. Persistence depends on the service (`InMemorySessionService` loses everything on restart; `Database`/`VertexAi` persist). Source: <https://adk.dev/sessions/state/>
- **OpenAI Agents SDK Sessions**: an ordered item list per session id with **destructive mutators** — `pop_item()` ("Remove and return the most recent item," documented as the correction mechanism) and `clear_session()`. Backends: `SQLiteSession`, `AsyncSQLiteSession`, `RedisSession`, `SQLAlchemySession`, `MongoDBSession`, `DaprSession`, `OpenAIConversationsSession`, `OpenAIResponsesCompactionSession`, `AdvancedSQLiteSession` (the only one advertising branching), `EncryptedSession`. Retrieval control is a count cap (`SessionSettings(limit=N)`) plus a merge callback. Source: <https://openai.github.io/openai-agents-python/sessions/>
- **CrewAI** has the closest thing to our scope tree, and it is LLM-inferred: a unified `Memory` class with "a hierarchical tree of scopes, similar to a filesystem" (`/`, `/project/alpha`, `/agent/researcher`); "the LLM analyzes the content and the existing scope tree, then suggests the best placement"; ranking is "composite scoring that blends semantic similarity, recency, and importance" with tunable `recency_weight`, `semantic_weight`, `importance_weight`, `recency_half_life_days`; default embeddings `text-embedding-3-large`. Deletion is real deletion: `memory.forget(scope="/project/old")`. Source: <https://docs.crewai.com/en/concepts/memory>
- Retrieval is embedding-first in CrewAI (semantic similarity is a first-class scoring term), the opposite of exact-first.

### 13. Manus — todo.md as attention control (and a live cautionary tale)

- The engineering post is real and specific. Average task ≈ **50 tool calls**; average input:output token ratio ≈ **100:1**; KV-cache economics quoted concretely: "with Claude Sonnet… cached input tokens cost **0.30 USD/MTok**, while uncached ones cost **3 USD/MTok — a 10x difference**." Source (archived; see live-site note below): <https://web.archive.org/web/20260101231329/https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus>
- **Append-only context is a stated design rule**: "Make your context append-only. Avoid modifying previous actions or observations. Ensure your serialization is deterministic." Same URL.
- **Filesystem as unbounded memory with restorable compression**: "we treat the file system as the ultimate context in Manus: unlimited in size, persistent by nature, and directly operable by the agent itself… Our compression strategies are always designed to be **restorable**. For instance, the content of a web page can be dropped from the context as long as the URL is preserved." Same URL.
- **`todo.md` rewriting is deliberate attention manipulation, not task tracking**: "By constantly rewriting the todo list, Manus is **reciting its objectives into the end of the context**. This pushes the global plan into the model's recent attention span, avoiding 'lost-in-the-middle' issues and reducing goal misalignment." Same URL.
- **Keep failures in the log**: "leave the wrong turns in the context… Erasing failure removes evidence. And without evidence, the model can't adapt." Same URL.
- Tool availability is managed by **logit masking over a state machine**, never by mutating tool definitions (which would invalidate KV cache and cause "schema violations or hallucinated actions"). Same URL.
- **Vapour/risk signal (dated, first-hand)**: manus.im was serving a maintenance page on 2026-08-24: "We are processing scheduled data deletion to comply with regulatory requirements in specific jurisdictions as Manus prepares to resume operations as an independent company. Some users in specific jurisdictions are temporarily unable to access Manus during this process, and will be available at 8:00 a.m. on August 25, 2026 (SGT)." Source: <https://manus.im/maintenance> (footer reads "© 2026 Manus AI · Singapore"). The engineering ideas are sound; the vendor is mid-restructure and its own blog was unreachable at time of writing.

### 14. Spec-driven tooling: GitHub Spec Kit and AWS Kiro

- **Spec Kit** is large and active: **131k stars, 11.8k forks, 1,854 commits**, `1.0.0` reached one year after first commit. Source: <https://github.com/github/spec-kit>

Source: <https://raw.githubusercontent.com/github/spec-kit/main/README.md>

## What is proven vs claimed

**Proven (first-party numbers, or mechanism visible in shipped docs/source):**

- Multi-agent research beats single-agent on breadth-first tasks by 90.2% internally, and token volume explains 80% of BrowseComp variance — Anthropic's own measurement, published. Also proven: it costs ~15× chat token usage. <https://www.anthropic.com/engineering/multi-agent-research-system>
- Filesystem-as-memory works and is the industry default. Independently shipped by Anthropic (artifact store), Manus (restorable compression), OpenHands (`MEMORY.md`), and every `AGENTS.md` adopter.
- Copilot Memory's citation-validation loop is a shipped mechanism, not a whitepaper: facts carry citations, citations are re-checked against the current branch, and only validated facts are used. <https://docs.github.com/en/copilot/concepts/agents/copilot-memory>
- Claude Code agent teams' shared task list with dependencies and **file-locked claiming** is shipped and documented at the file-path level. <https://code.claude.com/docs/en/agent-teams>
- OpenHands' judge-gated goal loop with persisted, resumable status is shipped with API endpoints and typed verdicts. <https://docs.openhands.dev/sdk/guides/agent-server/conversation-goals>
- Devin Dynamic Workflows' hash-keyed replay is shipped, with the determinism constraints spelled out and a 7-day max run. <https://docs.devin.ai/work-with-devin/dynamic-workflows>
- Hard operational ceilings are real and published: 59-minute Copilot sessions, one branch / one PR per task, single repo (<https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent>); 80k/40k char AGENTS.md caps (<https://docs.factory.ai/harness/agents-md>); ~6,000-char OpenHands memory budget (<https://docs.openhands.dev/sdk/guides/persistent-memory>); 1k default repo-map tokens (<https://aider.chat/docs/repomap.html>); 100 held messages / 5-min dialog expiry / 12-hour idle subscription (<https://code.claude.com/docs/en/cross-session-messaging>).

**Claimed, unproven, or marketing-shaped:**

- "10x more autonomous" and "200 minutes" (Replit) are vendor claims with no published eval, benchmark, or success-rate-versus-duration curve. <https://replit.com/blog/introducing-agent-3-our-most-autonomous-agent-yet> Coverage of the same launch reported billing complaints from the autonomy change (<https://www.theregister.com/2025/09/18/replit_agent3_pricing/>) — secondary, but the pricing backlash is a real signal that long autonomous runs are economically hazardous.
- "Don't build multi-agents" is an argument, not a measurement — Yan presents no eval, and Cognition subsequently shipped parallel Managed Devins and Dynamic Workflows. Treat the essay as a well-argued prior, not evidence. <https://cognition.com/blog/dont-build-multi-agents> vs <https://docs.devin.ai/work-with-devin/advanced-capabilities>
- "60k open-source projects" for `AGENTS.md` is a GitHub code-search count of *file existence*, not of usefulness, currency, or agent adherence. The query is disclosed, so it's checkable — but it measures adoption of a filename. <https://agents.md/>
- Anthropic's 90.2% figure is on an **internal** research eval with no published rubric or dataset. Same for the "40% decrease in task completion time" from the tool-description-rewriting agent. Not independently reproducible.
- Spec Kit's `converge` "Converged" verdict, Kiro's EARS acceptance criteria, and OpenHands' judge verdict are all **LLM judgements presented as gates**. None is a deterministic predicate. The gate is as reliable as the judge, and no vendor publishes judge precision/recall.
- CrewAI's "LLM infers scope, categories, and importance" is a claim about routing quality with no published accuracy. Scope misplacement is silent. <https://docs.crewai.com/en/concepts/memory>

## Where it breaks / what it cannot do

1. **Nobody has a durable shared *fact* store across concurrent agents.** Every production system either (a) passes text messages with no history (Claude Code cross-session messaging: "never conversation history or files"), (b) hands off through git branches (Devin Dynamic Workflows, Cursor Cloud Agents, Copilot), or (c) returns a summary to a parent (Anthropic subagents). Cognition names this as the open problem and says nobody is working on it.
2. **All the memory stores are last-write-wins blobs.** ADK `session.state` is a mutable serializable dict. OpenAI Agents SDK Sessions expose `pop_item()`/`clear_session()` as the *documented* correction mechanism — i.e. corrections are destructive. CrewAI `forget()` deletes. Copilot Memory deletes at 28 days. Replit rollback "removes all changes made after that point." **No production system I found stores a superseded record.** There is no assert-time anywhere.
3. **No provenance requirement anywhere except Copilot Memory, and even there it is one field.** Copilot stores citations and validates them; it does not carry a confidence class, an instrument, a protocol, or a distinction between measured / human-confirmed / derived / unverified. No system rejects a write for missing provenance.
4. **Repo-file-as-memory has hard character ceilings and no conflict semantics.** 80k chars initial + 40k dynamic (Factory), ~6k chars (OpenHands `MEMORY.md`), "under 500 lines" per rule (Cursor), 1k tokens (Aider map). Conflict resolution is *proximity*: "The closest AGENTS.md to the edited file wins" (<https://agents.md/>). Two files asserting different values for the same fact do not raise anything — the nearer one silently wins. With 88 `AGENTS.md` files in one repo (OpenAI's own), that is a lot of silent shadowing.
5. **Memory files are a prompt-injection surface, and at least one vendor says so.** OpenHands wraps injected memory in `<UNTRUSTED_CONTENT>` and instructs the agent to "treat them as unverified hints, never as authoritative instructions," precisely because "a cloned repo may ship a `.openhands/memory/MEMORY.md`." Repo-file-as-memory is *attacker-writable via PR*. <https://docs.openhands.dev/sdk/guides/persistent-memory>
6. **The one real shared task list is single-machine and unversioned.** Claude Code teams coordinate through `~/.claude/teams/.../inboxes/*.json` and `~/.claude/tasks/{team}/` with **file locking** — which means it cannot span machines, is invisible across container boundaries ("A container has its own filesystem, so a session inside it and a session on the host can't reach each other"), is experimental and off by default, and the docs warn of "known limitations around session resumption, task coordination, and shutdown behavior."
7. **Synchronous orchestration is the acknowledged bottleneck and remains unfixed.** Anthropic: lead agents "execute subagents synchronously… the lead agent can't steer subagents, subagents can't coordinate, and the entire system can be blocked while waiting for a single subagent." OpenHands ships the same shape — its Task Tool Set is documented as "Delegate complex work to specialized sub-agents that **run synchronously** and return results to the parent agent" (<https://docs.openhands.dev/llms.txt>, entry for <https://docs.openhands.dev/sdk/guides/task-tool-set>). Async is described as future work by the vendor that measured it.
8. **Determinism is bought by forbidding the outside world.** Devin's replay only works if "prompts must not depend on the current time or date, randomness, generated IDs, environment variables, filesystem state, or network responses." A memoized orchestration and a live fact store are in tension: any read of mutable shared state breaks the hash key.
9. **Operational ceilings make long missions impossible inside one session.** 59 minutes hard (Copilot), one branch and exactly one PR per task, one repo per run. Devin caps a workflow run at 7 days. Missions longer than a session must live *outside* the agent, and today they live in a human tracker.
10. **Contradiction handling is a scheduled LLM chore.** Devin's answer to conflicting knowledge is to ask Devin, on a cron, to "resolve conflicting guidance" and propose consolidations. There is no contradiction object, no blocking, no notification at write time.
11. **Cost is the real limit, and it is under-instrumented.** 15× chat tokens for multi-agent (Anthropic); "Higher: each teammate is a separate Claude instance" (Claude Code teams); "one run can consume far more ACUs than doing the same task in a single session" with the explicit advice to pilot on a slice first (Devin workflows). Nobody publishes cost-per-resolved-task.

## What we should steal

1. **Copilot Memory's citation-validation loop — this is the single best idea in production.** Store the evidence pointer with the fact, then *re-verify the pointer against current reality before use*. "Only validated facts are used." <https://docs.github.com/en/copilot/concepts/agents/copilot-memory> We should generalise it: our `evidence: {repo, commit, protocol, instrument}` is exactly the pointer, and a fact whose evidence no longer resolves should be automatically demoted, not silently trusted.
2. **Write authority gated on repo write access.** Copilot only creates repo-level facts from users with write access. Same URL. Cheap, effective, maps directly onto our provenance/confidence classes.
3. **Claude Code's task semantics, wholesale**: three states, explicit dependencies, "a pending task with unresolved dependencies cannot be claimed," automatic unblocking on completion, and atomic claiming. <https://code.claude.com/docs/en/agent-teams> Replace file locking with a real transaction; keep the model.
4. **`TaskCreated` / `TaskCompleted` / `TeammateIdle` hooks with "exit code 2 blocks and returns feedback."** Same URL. This is the reached/not-reached gate we want, and it already has proven ergonomics: the gate can *refuse* a completion and hand back a reason.
5. **OpenHands' goal object**: an objective + iteration cap + typed verdict `{score, complete, missing}` + status `{running, complete, capped, interrupted}`, **persisted into the event log so it survives restart**, with terminal statuses non-resumable and 409 on concurrent goals. <https://docs.openhands.dev/sdk/guides/agent-server/conversation-goals> The `missing` field is the good part — a not-reached gate that carries *what is missing* is actionable; a boolean is not.
6. **OpenHands' `source` vs `role` separation.** "These fields are intentionally independent. Do not infer event origin from LLM role." <https://docs.openhands.dev/sdk/arch/events> Attribution must be a separate axis from presentation. Our provenance should never be inferable from how a record renders.
7. **Compression as an event, never a deletion.** `Condensation{forgotten_event_ids, summary, summary_offset}` (same URL) and Manus's rule that "compression strategies are always designed to be restorable" — drop the page body, keep the URL. Both are append-only by construction.
8. **Keep failures.** "Leave the wrong turns in the context… Erasing failure removes evidence." <https://web.archive.org/web/20260101231329/https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus> A bitemporal store gets this free; make sure retrieval surfaces failed attempts, not just live values.
9. **`todo.md` recitation as a retrieval policy.** Manus's finding is that the mission must be re-injected *near the end of context*, not just stored. Same URL. Our mission object needs a "recite current targets" projection, not merely an API.
10. **Devin's hash-keyed replay for orchestration.** Keying an agent call by hash of prompt + schema + settings, so edits re-run only the affected subtree, is the right shape for expensive fan-out. <https://docs.devin.ai/work-with-devin/dynamic-workflows>
11. **Devin Knowledge's scope ladder and trigger-based retrieval**: org → enterprise scope, repo pinning (none / one / all), folders with bulk enable/disable, mandatory trigger description, lazy retrieval "when relevant, not all at once." <https://docs.devin.ai/product-guides/knowledge> Our global→project→mission→agent ladder is the same idea with two more levels; steal the *pinning* concept and the mandatory retrieval trigger.
12. **Aider's exact-first, embedding-free retrieval.** Tree-sitter symbols + graph ranking within a token budget, no vectors. <https://aider.chat/docs/repomap.html> Direct precedent for our exact-first stance.
13. **Peer messages are text with no authority.** Claude Code: a peer message "can't approve anything," can't change config, and slash commands arrive as inert text. <https://code.claude.com/docs/en/cross-session-messaging> Adopt this verbatim for our registry: an agent-authored write can never escalate its own confidence class or bypass a gate.
14. **Publish the caps.** Factory's 80k/40k, OpenHands' 6k, Cursor's 500 lines. Documented budgets change user behaviour; undocumented ones produce silent truncation.

## What we should deliberately do differently, and why

1. **Bitemporality — because every production system corrects by destroying.** `pop_item()` (OpenAI Agents SDK), `forget()` (CrewAI), 28-day deletion (Copilot Memory), "removes all changes made after that point" (Replit rollback). No prior art keeps the superseded record. That is why none of them can answer "what did we believe on Tuesday, and when did we learn otherwise?" — which is the only way to debug a multi-agent system that acted on a stale fact. Supersede-by-new-record is our differentiator, and nothing in production contradicts it.
2. **Provenance mandatory and server-enforced — because Copilot proves the value and nobody enforces it.** Copilot's citation validation demonstrably improves fact quality, but it is one vendor, one field, one scope. Rejecting unprovenanced writes at the API boundary is a strictly stronger position, and the OpenHands `<UNTRUSTED_CONTENT>` wrapper shows the alternative: without provenance you are reduced to labelling your entire memory "unverified hints, never authoritative."
3. **Declared scopes, not LLM-inferred ones.** CrewAI has the tree we want but places records by LLM inference (<https://docs.crewai.com/en/concepts/memory>), which fails silently and unauditably. ADK gets this right with mechanical prefixes (`user:`, `app:`, `temp:`) (<https://adk.dev/sessions/state/>). Take ADK's determinism and CrewAI's hierarchy; reject the inference.
4. **Nearer-scope-wins must raise a contradiction, not silently shadow.** `AGENTS.md`'s rule — closest file wins (<https://agents.md/>) — is fine for instructions and catastrophic for facts. With 88 files in one repo, silent shadowing is the normal case. A first-class contradiction object is the fix, and the closest production behaviour (Devin's cron-scheduled "resolve conflicting guidance") shows what happens without one: conflicts accumulate until a human schedules a cleanup.
5. **Machine-checkable gates, not judge-only gates.** Everyone with a gate uses an LLM: OpenHands' judge LLM, Spec Kit's `converge`, Kiro's EARS prose. EARS is explicitly a *natural-language* discipline (<https://en.wikipedia.org/wiki/Easy_Approach_to_Requirements_Syntax>). Our mission targets should be deterministic predicates over stored facts (metric X measured at ≥ Y with confidence class ≥ measured) with a judge as an *optional* fallback channel — the inverse of the current default. Note OpenHands' good instinct to steal regardless: fail closed on unparseable verdicts (`score=0.0, complete=False`).
6. **Cross-machine by construction.** Claude Code teams and cross-session messaging are filesystem-scoped and admit it (containers and host cannot reach each other; WSL2 and native Windows cannot reach each other). We are explicitly remote and multi-project, so filesystem-scoped coordination is disqualified from the start — including its file-locking claim mechanism, which must become a server-side transaction.
7. **Registry with heartbeats — no prior art at all.** Cursor tracks environment + Build version per run (<https://cursor.com/docs/cloud-agent>); Devin's coordinator polls children and "schedules messages to itself" to check back (<https://docs.devin.ai/work-with-devin/advanced-capabilities>); Claude Code has a 12-hour one-shot idle subscription and no liveness model (<https://code.claude.com/docs/en/cross-session-messaging>). Every system polls or waits. A registry where agents, worktrees, branches and webhooks are nodes with heartbeats is genuinely absent from production — build it, and treat its absence as the reason coordinators everywhere are reduced to polling.
8. **Do not make the event log the retrieval path.** OpenHands' append-only event log is the right substrate but is also the agent's memory, which forces a condenser and a 6k-char index on top. Keep the log as source of truth and project *queryable facts* out of it — exact-first structured + full-text, embeddings labelled as a fuzzy secondary channel. Aider's embedding-free graph ranking (<https://aider.chat/docs/repomap.html>) is the existence proof that useful code retrieval does not require vectors.
9. **Budget the mission, and say so.** Every real system has a hard ceiling — 59 minutes (Copilot), 200 minutes (Replit), 7 days (Devin workflows), 10 audit rounds (OpenHands default `max_iterations`). Our mission object should carry an explicit budget and a terminal `capped` status like OpenHands', rather than pretending missions run forever. Also copy Devin's cost discipline verbatim: pilot fan-out on a slice and check consumption before pointing it at the whole repo.
10. **Assume the memory store is attacker-writable and design for it.** OpenHands is the only vendor honest about this. Our provenance classes are the right answer — an unverified, agent-asserted record must be structurally incapable of satisfying a mission gate that requires measured or human-confirmed evidence. That property is what makes a mandatory-provenance store worth more than a smarter `AGENTS.md`.
11. **Expect to be the async layer nobody built.** Anthropic named async subagent coordination as the next unlock and listed its costs: "result coordination, state consistency, and error propagation across the subagents" (<https://www.anthropic.com/engineering/multi-agent-research-system>). Those three are precisely what a bitemporal, provenanced, contradiction-detecting store addresses. That is the strongest available argument that this design is aimed at a real, vendor-acknowledged gap rather than an invented one.
